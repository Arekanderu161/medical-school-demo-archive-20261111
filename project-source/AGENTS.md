# AGENTS.md — Онлайн-школа УЗИ (Анастасия Крылова / демо «Практика»)

## 1. Текущее состояние проекта

Репозиторий содержит интерактивное веб-демо одного курса УЗИ щитовидной железы (Этап 0 — прототип для согласования с клиенткой), без Telegram, реальной оплаты, настоящей авторизации и облачного backend:
- **Рабочие точки входа**: `src/main.tsx`, `src/App.tsx`, `src/school/`.
- **Модели демо**: `src/school/domain.ts`, данные — `src/school/data.ts`, локальное состояние — `src/school/repository.ts`, компоненты — `src/school/components.tsx`, стили — `src/school/styles.css`.
- **Тесты**: `tests/demoSchool.test.ts` (Vitest) и `tests/school.pw.ts` (Playwright E2E).
- Плеер в демо — локальный интерактивный макет слайдов, не видеозапись. Пособие сохраняется в PDF через диалог печати браузера, не через серверную генерацию.
- Клиентские ограничения в `DemoSchoolRepository` предназначены только для показа сценариев и не являются защитой контента.

## 2. Целевой стек рабочей платформы (Этап 1)

| Часть | Решение |
| :--- | :--- |
| **Серверная логика** | **NestJS + TypeScript** |
| **База данных** | **PostgreSQL** |
| **Работа с БД и миграции** | **Prisma** |
| **Вход** | Email-код или одноразовая ссылка, отзываемые серверные сессии |
| **Пособия** | Приватное S3-совместимое хранилище, персональная маркировка PDF на сервере (номер лицензии) |
| **Видеоуроки** | Специализированный видеохостинг (предварительно рассматривается **Kinescope**) |
| **Оплата** | Один платёжный провайдер после уточнения страны и формы деятельности |
| **Развёртывание** | **Docker**, HTTPS, резервные копии и мониторинг |

## 3. Обязательные архитектурные и продуктовые правила

1. **Не расширять демо сложной клиентской админкой на `localStorage`**:
   - До фиксации итогов встречи с клиенткой не строить многокурсовую систему и редактор курсов на локальных данных.
   - При переходе к разработке платформы следовать порядку из [`CODEX_PLAN.md`](./CODEX_PLAN.md): сначала спецификация БД/API и один сквозной серверный сценарий (Vertical Slice), затем админка и управление школой.
2. **Ключевые принципы серверной модели данных**:
   - Курсы имеют стабильный произвольный `id` и отдельный `slug` (не использовать захардкоженные литералы в типах).
   - Строго разделять `Course` (программа), `Tariff` (предложение о покупке), `Order` (зафиксированные условия на момент покупки) и `Access` (выданный доступ ученика с основанием выдачи).
   - Контент и отдельные сущности материалов (`Material`) должны поддерживать состояния `draft`, `published`, `archived`.
   - Обратная связь проектируется как диалог (`Thread` + `Message[]`) с явным правилом расходования лимита вопросов.
   - Роли (`student`, `assistant`, `author`, `admin`) реализуются через гранулярные серверные разрешения (помощник не обязан видеть клинические вопросы, автор — настройки платежей).
   - Техническая поддержка должна быть доступна на странице входа/оплаты (до авторизации).
3. **Юридические и контентные границы**:
   - Не собирать в демо реальные email, платёжные реквизиты и данные пациентов.
   - Не обещать абсолютную защиту от копирования/записи экрана, гарантированные продажи или пассивный доход без участия автора.
   - Не использовать спорные материалы «Докстарклаб» до выяснения договорных прав; не добавлять вымышленные отзывы, квалификации, удостоверения ПК и баллы НМО.

## 4. Команды разработки и проверки

Требуется Node.js 22 или 24. Команды выполняются в папке `medical-school-demo`:

```bash
npm run dev        # локальный сервер (http://127.0.0.1:3000)
npm test           # модульные тесты (Vitest)
npm run typecheck  # проверка типов TypeScript
npm run build      # сборка статики в dist/
npm run test:e2e   # E2E-тесты в Google Chrome (Playwright)
```
